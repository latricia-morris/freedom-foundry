# Freedom Foundry Portfolio Component  
## Replit Build Brief

## Purpose

Build a complete **Portfolio Publishing Engine** inside Freedom Foundry.

This component must make portfolio updates a normal part of project closeout—not a separate, manual marketing project that requires the agency to recreate project details, descriptions, visual selections, SEO fields, and page layouts over and over.

Freedom Foundry already functions as the operational/client portal layer. It should use the project information, client assets, delivery records, and approved work inside the system to prepare portfolio content quickly.

The system must support two public outcomes:

1. A deeper, authority-building public case study for **The Brand Revivalist®**.
2. A shorter, visually led public proof page for **Freedom Foundry**, so people who find the app through digital offers, tools, diagnostics, or resources can immediately see the agency’s work and inquire about services.

The system must never automatically publish public content. AI can draft and organize; an authorized Admin must review, approve, and publish.

***

# Core Principle

```text
Client project is completed
        ↓
Final delivery is released
        ↓
Freedom Foundry automatically creates a private Portfolio Review record
        ↓
Admin selects public-safe visuals, verifies permissions, edits copy,
reviews SEO and social metadata
        ↓
Admin approves public output
        ↓
TBR case study and/or Freedom Foundry proof page publishes
```

The portfolio system should make it possible to consistently publish portfolio work without making LaTricia or the agency team recreate the project from scratch.

***

# Brand Roles

## The Brand Revivalist®

The Brand Revivalist® is LaTricia Morris’s personal authority brand.

The Brand Revivalist public case-study output must be the deeper, more strategic, authority-building version of each public project.

Preferred final URL structure:

```text
https://thebrandrevivalist.com/work/[project-slug]
```

If that routing is not technically available at launch, support:

```text
https://work.thebrandrevivalist.com/[project-slug]
```

The public work library should look like a premium, design-forward, app-quality portfolio—not a generic WordPress archive.

## Freedom Foundry

Freedom Foundry is the operational platform, client portal, project-delivery system, and agency ecosystem.

Freedom Foundry may also publish a shorter public proof page so visitors who enter through a digital offer, resource, assessment, or lead-generation tool can see the quality and range of agency work.

Example URL:

```text
https://freedomfoundry.vip/work/[project-slug]
```

## Public-content rule

One approved project record may create two public outputs:

```text
The Brand Revivalist® Authority Case Study
        +
Freedom Foundry Public Proof Page
```

The outputs may reuse accurate client facts, project scope, services, approved visuals, and permission records.

They must not use identical long-form copy, identical metadata, or an identical page purpose.

# The Brand Revivalist® Case Study Output

## Purpose

The TBR case study is the detailed, authority-building public project page.

It must show strategic thinking and first-hand expertise—not simply list deliverables or display images.

## Required page elements

```text
Hero Visual
Client / Project Identity
Location · Industry · Project Type, when approved
One-Line Transformation
Company Overview
The Challenge
Strategic Diagnosis
The Work / Approach
What Was Built
What Changed / Outcome
Selected Visual Proof
Testimonial, if approved
Related TBR Services
Related TBR Insight or Method
Visible TBR Attribution
Apply CTA
```

## Required attribution

Display this near the project story:

```text
Strategic direction led by LaTricia Morris, The Brand Revivalist®.
```

Link the name to a stable TBR About, Authority, or Method page.

## Conditional page behavior

```text
No testimonial:
Hide the testimonial section.

No verified numerical result:
Use “What Changed” and describe only factual outcomes.
Never invent metrics.

No public guideline permission:
Hide guideline visuals.

No detailed story yet:
Allow a polished Selected Work page with actual project facts, services,
visuals, and concise narrative.

No permission to name client:
Use approved anonymous case-study format.

No public permission:
Keep page private or Private Proof Only.
```

## Writing model

Use clear, specific, natural language.

The content should give prospects and search systems true context about the company, the challenge, the scope, and the strategic transformation.

Base pattern:

```text
[Client Name] is a [location/market] [industry] business serving [audience].

When the company outgrew [specific business or brand challenge], The Brand
Revivalist® led a [project type] engagement spanning [actual services and
deliverables]. Rather than treating the work as isolated design tasks, the
engagement created [specific cohesive transformation] across [actual
touchpoints].
```

Example:

```text
When a Lancaster, Pennsylvania business outgrew the logo and website that had
carried it to this stage, it needed more than a cosmetic update. The Brand
Revivalist® led a connected rebranding engagement across visual identity,
website design, business cards, brochures, and trade-show materials—turning
disconnected touchpoints into a cohesive brand system built to reflect the
company’s expertise.
```

Every generated paragraph must be editable by Admin.

# Definition of Done

The Portfolio Component is complete when:

1. Final client delivery automatically creates a private Portfolio Review record unless the project is marked Never Public or Private Proof Only.
2. The Portfolio Admin clearly shows what is published, pending, permission-pending, missing SEO, missing featured image, private proof only, and archived.
3. The agency can filter work by project type, work type, industry, client, year, status, permission, featured image, and SEO completeness.
4. Smaller deliverables—including logos, websites, social template kits, business cards, brochures, sales collateral, packaging, signage, and activation materials—are captured as work/service tags and portfolio evidence.
5. Industry is shown on individual project pages but public gallery filters focus on the work/services delivered.
6. The Admin can select public-safe visuals, choose a featured image, edit crop, reorder galleries, write captions, write alt text, and prevent private assets from appearing publicly.
7. FatJoe SEO reports can be stored privately and used only for editable AI suggestions.
8. AI never publishes automatically or invents client facts, permissions, testimonials, results, industries, locations, or rankings claims.
9. One Portfolio Review record can create a detailed TBR case study and a distinct Freedom Foundry proof page.
10. TBR and Freedom Foundry pages have separate titles, copy, metadata, CTAs, indexing settings, canonical settings, and social images.
11. Every indexable public project page has a stable URL, crawlable text, unique H1/title/meta description, appropriate canonical, sitemap inclusion, accurate image metadata, and TBR attribution.
12. Every publication requires explicit Admin approval.
13. Private proof pages are noindex, excluded from sitemaps/galleries, view-only, and revocable.
14. The system never exposes source files, raw Drive URLs, internal notes, contracts, invoices, credentials, unapproved work, or client-private assets publicly.
